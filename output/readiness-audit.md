Обновление после исправлений: все четыре проблемы из раздела ниже исправлены в исходниках. Docker Compose получает APP_URL; запуск прерывается после двух ошибок миграции или при отсутствии DATABASE_URL; CORS разрешает PATCH; WebSocket переподключается с задержкой 1–30 секунд и запрашивает обновление данных после восстановления. ## Найденные проблемы

1. **Запуск Docker dev/staging сломан конфигурацией.** В `docker-compose.yml` и `docker-compose.staging.yml` для приложения указан `NODE_ENV=production`, но не передаётся `APP_URL`. При этом `server/src/app.ts:43` выбрасывает ошибку без `APP_URL`, а `.env` исключён из Docker-контекста. В production Compose эта переменная передаётся корректно.
2. **Приложение запускается после неудачной миграции.** `docker-entrypoint.sh:12` после двух ошибок миграции продолжает запуск сервера. Это позволяет начать работу с несовместимой схемой. Для готовности требуется остановка с ненулевым кодом при окончательном сбое миграции.
3. **CORS не разрешает PATCH.** `server/src/app.ts:56` возвращает только `GET, POST, PUT, DELETE, OPTIONS`. Подтверждено OPTIONS-запросом к API. При прямом обращении браузера с другого домена PATCH-запросы, например смена статуса ремонта, не пройдут. Same-origin обращения через прокси этим не затронуты.
4. **Нет восстановления WebSocket после обрыва.** `src/hooks/useRealtimeSync.ts` создаёт соединение только при изменении token; повторное соединение после `close`/`error` не реализовано. Обновления между кассами могут перестать приходить до обновления страницы.

## Ограничения и дополнительные замечания

- Проверка интерфейса — smoke test загрузки разделов; она не подтверждает каждую кнопку, все варианты расчётов и весь UX.
- Публичные Vercel/Render окружения и их реальные переменные не проверялись. Для такого развёртывания нужно проверить `VITE_WS_URL`, `APP_URL`, HTTPS и доступность backend.
- Полная сборка и запуск Docker-образов не выполнялись. Конфигурационные проблемы выше найдены по исходникам.
- Печать чеков, физическая камера/сканер, установка PWA на реальное устройство, резервное копирование/восстановление и нагрузка не проверялись.
- Существующий `scripts/test-e2e-all.ts` использует текущую DATABASE_URL, тестовые пароли и частичную очистку, включая удаление всех пустых transferRequest. Его нельзя считать безопасным для запуска на рабочей базе; в этой проверке он запускался только в изоляции.
- `scripts/audit-system.ts` ищет курс по UTC-дате, тогда как бизнес-дата приложения использует Asia/Tashkent. В первые пять часов местного дня проверка курса может относиться к предыдущему дню.
- Изменения в исходный код приложения в ходе этой проверки не вносились. Найденные проблемы пока не исправлены.
