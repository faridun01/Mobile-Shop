# Исходные замеры (до оптимизации)

Все цифры получены измерениями на этой машине; оценок и экстраполяций здесь нет.
Состояние кода: ветка `perf/optimization` с отложенными (stash) изменениями, то есть ровно коммит `a459446`.

## Среда измерений

| Параметр | Значение |
|---|---|
| Машина | Windows 11 Pro, Node 22, Postgres 16 в Docker (`mobile_shop_db`, порт 5435) |
| База | отдельная `perf_test`, перед каждым прогоном пересоздаётся из шаблона `perf_test_template`; рабочая `mobile_shop_db` не используется |
| Данные | 5 610 телефонов, 3 823 продажи, распределены по 90 дням (~43 продажи/день), ремонты, приходы, расходы, перемещения, журнал аудита; пользователи с случайными паролями, без реальных персональных данных |
| Сервер | `node --import tsx server/src/index.ts`, `NODE_ENV=production`, порт 3401 |
| Браузер | Chrome headless (puppeteer-core), кэш отключён. Профиль desktop: 1440×900. Профиль phone: 390×844, DPR 3, UA iPhone, **CPU throttling 4×** (эмуляция в Chrome, не настоящий iPhone) |
| Повторы | каждый GET: 1 прогрев + 7 замеров (медиана, p95); стартовый параллельный набор — 5 замеров; продажа — 20 продаж |

Скрипты: `PERFORMANCE_AUDIT/scripts/measure-bundle.mjs`, `measure-runtime.ts`, `screenshots.ts`, `setup-perf-db.ts`.
Сырые данные: `PERFORMANCE_AUDIT/data/bundle-before.json`, `runtime-before.json`, `build-before.log`.

Переход измеряется от `pushState` до 300 мс сетевой тишины (300 мс вычтены).
FCP на desktop больше, чем на phone, потому что в desktop-профиле страница грузится в только что запущенном браузере, где проходит холодный старт процесса отрисовки. Цифры приведены как измерены.
