# Исправления перед деплоем, 25.09.2026

Исправлены пять пунктов предрелизного аудита в исходниках. Рабочие контейнеры не пересоздавались, деплой не выполнялся. Пароли существующих пользователей по указанию владельца не менялись: их необходимо сменить вручную до публикации.

- Healthcheck во всех трёх Compose использует `127.0.0.1`.
- nginx перезаписывает X-Forwarded-For адресом подключившегося клиента в API и основном location. Поддельный заголовок проверен через отдельный настоящий nginx и Express: `203.0.113.66` заменён на реальный `127.0.0.1`. Конфигурация рассчитана на nginx как внешний edge; при добавлении другого прокси следует отдельно настроить доверенные адреса real_ip, не доверять произвольным заголовкам из интернета. Backend не должен публиковаться напрямую.
- CORS разрешает `Idempotency-Key`. Добавлена регрессия preflight.
- Seed сохраняет пароли и привязки существующих пользователей. Для новых пользователей нужны `SEED_PASSWORD_ADMIN`, `SEED_PASSWORD_PARTNER`, `SEED_PASSWORD_AHMAD`, `SEED_PASSWORD_FARHOD` (минимум 16 символов; задавать разные значения). Образец — `.env.example`. Тестовые пароли доступны только с `SEED_TEST_DATA=true`, в разрешённой локальной тестовой схеме/БД и вне production. CI и изолированные тесты обновлены. Секретные `.env*` и backups исключены из Docker build context.
- Backup публикует файл только после успешного pg_dump и проверки gzip. Restore сначала проверяет gzip и выполняет импорт в отдельную временную БД, затем создаёт канонический дамп. Удаление public и финальный импорт проходят в одной транзакции: ошибка откатывает их вместе. Пустой архив без public-таблиц отклоняется. Временная БД удаляется.

## Резервное копирование и восстановление

Запускать из Bash на Docker-хосте. Переменные: `DB_CONTAINER` (по умолчанию mobile_shop_db_prod), `DB_USER`/`POSTGRES_USER`, `DB_NAME`/`POSTGRES_DB`, `BACKUP_DIR`. Значения пользователя и БД по умолчанию — postgres и mobile_shop_db. Для restore нужны права создания временной БД и изменения целевой схемы.

```bash
DB_CONTAINER=mobile_shop_db_prod DB_USER=postgres DB_NAME=mobile_shop_db bash scripts/backup-db.sh
# Остановить запись приложения, сохранить свежую резервную копию, затем:
DB_CONTAINER=mobile_shop_db_prod DB_USER=postgres DB_NAME=mobile_shop_db bash scripts/restore-db.sh backups/selected.sql.gz
```

Восстанавливается public schema. Использовать только доверенные архивы: SQL-дамп содержит исполняемые команды. Остановить приложение до восстановления и запустить после успешного завершения. Внешние копии и расписание на сервере настраиваются отдельно.
