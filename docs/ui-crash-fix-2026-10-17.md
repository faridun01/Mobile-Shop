# Исправление UI crash — 17.10.2026

Исправлены подтверждённые дефекты из `ui-crash-diagnosis-2026-10-17.md`. Денежная логика и БД не менялись.

- DailyRateModal вызывает хуки до возврата для отсутствующего пользователя.
- RevisionPage разделена на проверку прав и дочерний экран администратора: смена пользователя не меняет порядок хуков одного компонента.
- Сохранённые категории расходов проверяются как массив объектов с непустыми строковыми id/label. Невалидные элементы пропускаются; недоступный localStorage не приводит к падению. Другие настройки и сессия не удаляются.
- Ленивые импорты маршрутов и сканера повторяются один раз при характерной ошибке загрузки модуля. Ошибки выполнения кода не повторяются. Принудительной автоматической перезагрузки нет.
- Отдельная граница ошибок вокруг страниц сохраняет навигацию и общий provider. При переходе на другой маршрут ошибка границы сбрасывается. Это не гарантирует сохранение локального состояния уже упавшего компонента.
- Экран сбоя различает ошибку загрузки раздела и прочие ошибки, показывает диагностический код. Последняя диагностическая запись сохраняется локально в `ms_last_ui_crash`: время, категория, маршрут без query, build commit и ограниченный componentStack. Произвольный текст исключения не сохраняется. Автоматической отправки на сервер нет.
- Раздача web-сборки backend вынесена в тестируемый модуль. Отсутствующие `/assets/*` получают 404/no-store вместо index.html; существующие hash-файлы сохраняют immutable-кэш, SPA-маршруты продолжают работать.

Проверки: 75 файлов / 471 тест, TypeScript и production web/PWA build успешны. Новые тесты проверяют переходы пользователя, рендер расходов при повреждённых настройках, ограниченный retry импорта, безопасную диагностику и реальные HTTP-ответы раздачи статики. Исходные сценарии с ожидаемыми исключениями преобразованы в регрессии успешного рендера.

Границы: точная причина присланного клиентом скриншота остаётся неизвестной. Реальный iPhone и обновление между двумя production-релизами не воспроизводились. Отсутствующий старый chunk после повторной попытки всё ещё требует загрузки актуальной версии через ручное обновление. Исправление ответа 404 действует при раздаче через backend; конфигурация статического хостинга Vercel и политика хранения старых assets не менялись. Изменения локальные, публикация не выполнялась.
