# Mobile Shop: системный аудит 17.10.2026

## Результат и границы заключения

В выполненных автоматизированных сценариях необъяснённых денежных и складских расхождений не обнаружено. Исправлена валидация календарных периодов отчёта. Добавлены регрессии отчётных дат, ревизии и полного цикла аксессуаров, а также воспроизводимая объёмная симуляция.

Это подтверждение перечисленных ниже сценариев, а не доказательство отсутствия ошибок во всех функциях проекта. Полное выполнение исходного требования «каждая функция, все связи, все отчёты» не подтверждено: инструментальное покрытие всех ветвей не измерялось, интерфейс и нативные устройства не проходили сквозную автоматизацию. Бизнес-процессы из разных наборов не объединены в одну общую трёхмесячную модель.

Рабочая БД не использовалась. Создан отдельный контейнер `mobile-shop-audit-20261017`, PostgreSQL 16, адрес `127.0.0.1:55439`, БД `mobile_shop_audit`, без рабочих томов. Каждый интеграционный набор создавал и удалял собственную схему. Миграции и seed выполнялись только там. Проверялось текущее рабочее дерево, включая существовавшие до аудита незакоммиченные изменения ревизии, прихода, обменов и сканера; эти изменения не приписываются данному аудиту.

## Актуальная архитектура

- React 19/Vite/Tailwind SPA и Capacitor. `AppContext`/zustand содержит общий слой данных, API-клиент добавляет сессию и ключ идемпотентности, WebSocket инициирует обновления. Старые записи загружаются диапазонами; проверка серверной полной истории не заменяет проверку всех экранов с ограниченным окном данных.
- Express `app.ts` регистрирует встроенные endpoints закупок и продаж и 25 каталогов доменных модулей. Routes обеспечивают HTTP/RBAC/store scope, services выполняют бизнес-транзакции Prisma/PostgreSQL.
- Деньги вычисляются Decimal. Исторические операции сохраняют USD и курс. Кассы и финансовые счета обновляются в транзакции; аудит, распределение прибыли и остатки являются связанными эффектами операций.
- Обёртка Prisma-транзакций вызывает `executeOperation`: ключ связан с пользователем, advisory lock сериализует одинаковые ключи, результат хранится вместе с изменениями. Hooks отправляют уведомления после commit.
- Телефоны учитываются по IMEI, планшеты по SN, аксессуары — карточками и FIFO-партиями. Приход в магазин переносит товар со склада; ревизия сохраняет результат сверки и не корректирует автоматически деньги или остатки.
- Возврат/обмен связан с исходным чеком, себестоимостью и историческим распределением прибыли. Погашение клиентского долга распределяется по конкретным продажам. Инкассация связывает магазин, Центральную кассу и при необходимости Бонусный счёт.

## Объёмная симуляция

Команда: `npm run test:quarter`, реализация — `scripts/test-quarter-simulation.ts`.

| Параметр | Фактически выполнено |
|---|---:|
| Условные операционные дни | 90, 01.07–28.09.2026 |
| Товарные карточки | 1000 |
| Телефоны / планшеты / аксессуары | 500 / 200 / 300 карточек |
| Физические единицы прихода | 3700 |
| Магазины модели | 3 торговые точки + главный склад; seed также содержит другие точки |
| Поставщики модели | 3 |
| Владельцы | администратор и партнёр; 60/40 в одной точке, администратор в остальных |
| Успешные изменяющие HTTP-запросы | 3785, включая настройку и вход |
| Продажи | 3400 |
| Расходы | 270 |
| Изменения дневного курса в цикле | 90 |
| Курсы USD/TJS | 9.50–11.50, 21 значение |
| Параллельность продаж | до 6 запросов, общие кассы и владельцы |

Закупочные цены различаются, цены продажи открытые, включая продажи ниже себестоимости. Не все 1000 цен уникальны: стоимость меняется по детерминированной формуле, модели и идентификаторы различны. В каждой карточке аксессуара закуплено 10 единиц, продано 9. Все 700 серийных устройств проданы.

Важная методика дат: операции действительно выполняются через HTTP и реальные PostgreSQL-транзакции. После каждой продажи/расхода тест задаёт `createdAt` и для расходов `paidAt` согласно условному дню. Курсы меняются в текущем бизнес-дне. Часы ОС/PostgreSQL, даты финансовых проводок и все прочие timestamps не переводятся на три месяца назад. Поэтому это проверка объёма, сохранённых курсов и календарных выборок продаж/расходов, а не полноценная эмуляция трёх месяцев работы часов, смен и сессий.

Независимая Decimal-модель рассчитывает деньги по входным ценам и курсам, а не по ответу сервиса. Ежедневно сверяются кассы и финансовые счета. В конце отдельно проверяются каждый магазин, каждый месяц, каждый владелец, проводки, количественные и стоимостные остатки.

| Контроль | Значение USD |
|---|---:|
| Закупки / открытый долг поставщикам | 179061.00 |
| Выручка | 207113.96 |
| Себестоимость проданного | 164517.00 |
| Расходы | 36.87 |
| Чистая прибыль | 42560.09 |
| Остатки аксессуаров, 300 единиц | 14544.00 |
| Денежный остаток модели | 207077.09 |
| Расхождение касс с независимой моделью и счетами | 0.00 |
| Расхождение стоимости закупок с продажами и остатками | 0.00 |
| Расхождение прибыли отчёта и владельцев | 0.00 |

Проверено равенство: 179061.00 = 164517.00 + 14544.00. Также 207077.09 + 14544.00 − 179061.00 = 42560.09. В данной модели закупки идут в долг, продажи оплачиваются наличными; частичные оплаты, возвраты и другие процессы проверяются отдельными наборами.

| Проблема | Воспроизведение и исправление | Регрессия |

Добавлена проверка реальной календарной даты и HTTP 400 для пустых/неполных параметров | 8 unit-кейсов и HTTP-проверки невозможных, неверных и неполных периодов |

| Устаревшая форма ответа сканирования в тесте | новый discriminator `kind: DEVICE` отсутствовал в ожидаемых ключах; сохранена строгая проверка отсутствия закупочной стоимости | `test:store-receipt` 9/9 |
| Недостаточное интеграционное покрытие новых аксессуарных связей | добавлены независимые ожидания ревизии, частичного возврата, обмена, денежных и количественных последствий | `test:functional` 18/18 |

## Не проверено и оставшиеся ограничения

- Нет доказательства полного покрытия всех функций, маршрутов и ветвей RBAC. Существующие сценарии проверяют конкретные положительные и отрицательные случаи; это не полноценный пентест.
- Не выполнена трёхмесячная смешанная модель, где все ремонты, долги, возвраты, выплаты и инкассации происходят вместе. Эти процессы успешно проверены отдельными наборами; объёмный oracle моделирует наличные продажи, закупки в долг, приходы и расходы.
- Не проверены реальные переходы бизнес-дня/месяца/квартала с работающим сервером и PostgreSQL, истечение сессии в таком календаре, аварийное восстановление/перезапуск во время commit. Границы дат и timezone имеют отдельные unit-тесты.
- Не проверены все экраны React, их realtime-refetch и полнота старых данных на UI, мобильная адаптивность, камера/сканеры, Android/iOS builds, push на устройствах.
- Не проверены фактические Excel-файлы экспортов, печать чеков и все варианты отчётных фильтров/комбинаций.
- Не проверены восстановление backup, production Docker/nginx/Vercel, миграция существующей рабочей БД и откат релиза. Миграции на новой пустой тестовой БД проходят.
- `npm audit` не является подтверждением отсутствия неизвестных уязвимостей и не проверяет конфигурацию production.
- Предупреждение сборки о размере chunks сохраняется; производительность экранов и SLA нагрузки не измерялись. 3400 продаж — число корректностных операций, не benchmark.

## Повторный запуск

В PowerShell использовать `npm.cmd`, если политика исполнения запрещает `npm.ps1`.

```powershell
docker run --detach --name mobile-shop-audit-20261017 --publish 127.0.0.1:55439:5432 --env POSTGRES_USER=audit --env POSTGRES_PASSWORD=isolated-audit-only --env POSTGRES_DB=mobile_shop_audit postgres:16-alpine
$env:DATABASE_URL='postgresql://audit:isolated-audit-only@127.0.0.1:55439/mobile_shop_audit?schema=public'
npm.cmd run test:quarter
npm.cmd run test:functional
npm.cmd run test:system
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

После аудита проверено отсутствие временных схем (осталась только `public`), созданный контейнер остановлен. Для повторного использования выполнить `docker start mobile-shop-audit-20261017` вместо `docker run`. Команда создания выше приведена для чистого запуска после удаления предыдущего контейнера. `test:quarter` дополнительно отказывается запускаться вне localhost, порта 55439 и БД `mobile_shop_audit`; внутри создаёт уникальную временную схему и удаляет её в finally. JSON-итог создаётся в `audit-quarter-result.json`; исходные локальные логи данного аудита собраны в `output/system-audit-2026-10-17/`.
